# Configuration (`valkey.conf`)

https://valkey.io/topics/valkey.conf/

Short page, mostly correct, but the quoting rules are wrong for single quotes and the page leaves out core config-file mechanics (`include`, stdin, precedence, CONFIG REWRITE side effects). Fix the quoting paragraph first: a reader writing `requirepass 'a\nb'` gets a literal backslash-n.

## Findings

### F1 [minor] INACCURATE: Single-quote and double-quote escape rules are wrong (`topics/valkey.conf.md:29`)
**Doc says:**
> Single-quoted string can contain characters escaped by backslashes, and double-quoted strings can additionally include any ASCII symbols encoded using backslashed hexadecimal notation "\\xff".

**Problem:** Single-quoted strings only recognize `\'`. Every other backslash is kept literally. Double-quoted strings support `\n \r \t \b \a`, `\xHH` for any byte (0xff is not ASCII), and `\<char>` for a literal char. None of that is stated.
**Evidence:** valkey@9.1.2:src/sds.c:1083-1087 (single-quote branch):
```
} else if (!isPtrExceedingEnd(p, 2, end) && (*p == '\\' && *(p + 1) == '\'')) {
    new_char = '\'';
```
Double-quote branch, src/sds.c:1059-1072, handles `\x` + two hex digits and `n r t b a`, default copies the next char. Live 9.1.2 run with `requirepass 'a\nb'` in the config file:
```
$ valkey-cli -p 21580 -a 'a\nb' config get requirepass | od -c
0000000   r   e   q   u   i   r   e   p   a   s   s  \n   a   \   n   b
```
**Fix:** Replace with: "Inside single quotes, only `\'` is an escape; every other character, including a backslash, is taken literally. Inside double quotes, `\n`, `\r`, `\t`, `\b`, and `\a` are expanded, `\xHH` inserts the byte with hex value HH (for example `\xff`), and a backslash before any other character inserts that character."

### F3 [minor] MISSING: CONFIG REWRITE side effects and failure mode not stated (`topics/valkey.conf.md:81`)
**Doc says:**
> you can use `CONFIG REWRITE`, which will automatically scan your `valkey.conf` file and update the fields which don't match the current configuration value. Fields non existing but set to the default value are not added.

**Problem:** It omits that non-default values absent from the file are appended (under a `# Generated by CONFIG REWRITE` marker), that values are re-quoted, and that the command fails if the server started without a config file. Readers who start with only command-line flags will hit an error.
**Evidence:** Live 9.1.2: file had `requirepass 'a\nb'` and no `dir`/`logfile`/`maxmemory`. After `CONFIG SET maxmemory 2mb maxmemory-policy allkeys-lru` and `CONFIG REWRITE`:
```
requirepass "a\\nb"

# Generated by CONFIG REWRITE
dir "/tmp/docreview-valkey.conf"
maxmemory-policy allkeys-lru
maxmemory 2mb
...
logfile "/tmp/docreview-valkey.conf/log"
```
valkey@9.1.2:src/config.c:3706: `addReplyError(c, "The server is running without a config file");`
**Fix:** Add after line 83: "Options set to a non-default value that are not in the file are appended at the end under `# Generated by CONFIG REWRITE`, including options passed on the command line. `CONFIG REWRITE` returns an error if the server was started without a config file." Link `CONFIG REWRITE` to [CONFIG REWRITE](../commands/config-rewrite.md).

### F4 [minor] MISSING: `include`, stdin config, and option precedence (`topics/valkey.conf.md:56`)
**Doc says:**
> The format of the arguments passed via the command line is exactly the same as the one used in the valkey.conf file, with the exception that the keyword is prefixed with `--`.

**Problem:** The page never mentions the `include` directive, reading config from stdin with `-`, or that later directives (command-line options come after the file) override earlier ones. These are the main things operators need when splitting or layering configs.
**Evidence:** valkey@9.1.2:src/config.c:544 `if (!strcasecmp(argv[0], "include") && argc == 2) {`; valkey@9.1.2:valkey.conf:42-44 `# include /path/to/local.conf ... # include /path/to/fragments/*.conf`; valkey@9.1.2:src/server.c:7576 `config_from_stdin = 1;`.
**Fix:** Add a section "Including other files and layering options": "`include /path/to/file.conf` loads another file in place; glob patterns such as `include /etc/valkey/conf.d/*.conf` are accepted. Pass `-` as the config file to read it from stdin (`echo 'port 6380' | valkey-server -`). Options given on the command line are applied after the file, and when the same directive appears more than once the last value wins."
